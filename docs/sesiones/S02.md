## Decisiones compatibles y consumidores

Sin intención seleccionada, C2 devuelve empty o partial; usable queda reservado a evaluación
por intención S04. Guardar/confirmar no completa metodología ni aprueba ciencia/análisis.
Las preguntas pendientes no bloquean Datos y no se repiten si ya tienen respuesta conocida.

Objetivos/hipótesis nuevos omiten ID, reciben UUID y pueden vincularse tras guardarlos.
JSON Pointer usa índices del documento resultante; las referencias entre elementos usan IDs.
CAS protege los índices frente a listas cambiadas en otra revisión. La UI desvincula de forma
explícita hipótesis al retirar su objetivo; el servidor rechaza referencias rotas atómicamente.
Reaplicar tras 409 sustituye únicamente los campos locales; una lista sustituye su lista
completa. No hay combinación automática. Si otra revisión retiró IDs, se ajusta el borrador
o se usa la versión del servidor; nunca se crean IDs ficticios para resolver el conflicto.

C4 usa Fact para observations y algorithm_version en procedencia derived; contexto se
referencia por project_id; variables del snapshot son una proyección elegida del diccionario.
Detalles y consumidores S03/S04: [contratos v2](../../contracts/v2/README.md).
Los ejemplos sintéticos C4 son fixtures estáticos con manifiestos/CSV comprobables; no se
materializan snapshots en el servidor ni se inventan datasets al guardar un proyecto.
El futuro resolver S04 debe verificar existencia, pertenencia, revisión/hash, columnas y
fuentes sin ciclos: la validación estructural no reemplaza autorización ni resolución.
